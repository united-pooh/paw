# Select 工具完整迭代设计

日期：2026-07-31

## 1. 背景与目标

现有 Select 工具有两个主要问题：

1. 工具完成后展开详情只显示原始 JSON，无法直接看到原问题和用户选择的可读答案。
2. 选择界面的层级、焦点和滚动提示不清晰；当选项超过可用高度时，`more` 容易让用户误以为部分选项不存在。

本次改造是一次破坏性、完整的协议与 UI 迭代，不保留旧 `selected_ids` 结果格式。目标是：

- 选择阶段采用结构清晰的卡片式终端界面。
- 所有调用方提供的答案都可以访问，且界面明确展示总数和当前可见范围。
- Select 始终提供 `Custom option` 和 `Chat about this` 两个系统操作。
- 折叠后的工具摘要保持单行，不展示答案，避免额外占用 transcript 高度。
- 展开后展示原问题和已选答案，不展示未选项或原始 JSON。
- 工具结果直接返回可读的 `id` 和 `label`，而非仅返回 ID。

## 2. 范围

### 2.1 包含

- Select 结果协议从 `selected_ids` 迁移到 `selected_options`。
- Select dock 的布局、导航、滚动状态、系统操作和自定义输入状态。
- Select 工具在 transcript 中的折叠摘要和展开详情。
- 输入校验、broker 结果传递和相关测试的同步更新。
- 单选、多选、取消、自定义答案和讨论退出行为。

### 2.2 不包含

- 不增加控制 `Custom option` 或 `Chat about this` 是否显示的请求字段。
- 不为 `Chat about this` 增加独立的协议结果状态。
- 不保留 `selected_ids` 兼容字段或兼容分支。
- 不改变 Select 请求中的预设选项结构；预设选项仍包含 `id`、`label` 和可选 `description`。
- 不支持一次提交多个自定义答案。

## 3. 协议设计

### 3.1 结果结构

新增结果选项类型：

```go
type SelectedOption struct {
    ID    string `json:"id"`
    Label string `json:"label"`
}

type Result struct {
    Cancelled       bool             `json:"cancelled"`
    SelectedOptions []SelectedOption `json:"selected_options"`
}
```

成功结果示例：

```json
{
  "cancelled": false,
  "selected_options": [
    {"id": "whale", "label": "鲸鱼"},
    {"id": "custom_option", "label": "鸭嘴兽"}
  ]
}
```

取消结果示例：

```json
{
  "cancelled": true,
  "selected_options": []
}
```

`selected_ids` 被完全删除。工具实现、broker、dock 和测试不得继续生成或依赖该字段。

### 3.2 预设答案

预设答案的结果值直接来自请求中的选项：

- `id` 使用调用方提供的稳定 ID。
- `label` 使用用户在界面中看到的标签。
- 结果顺序遵循请求选项顺序，不遵循用户勾选先后顺序，以保证稳定输出。

### 3.3 自定义答案

自定义答案与预设答案使用相同结构：

```json
{"id": "custom_option", "label": "用户输入内容"}
```

规则：

- `custom_option` 是 Select 保留 ID。
- 请求中的普通选项不得使用 `custom_option`；解码时应返回明确错误。
- 每次 Select 最多存在一个自定义答案。
- 多选模式再次进入自定义输入时，编辑已有答案，不追加第二项。
- 自定义文本须去除首尾空白；空文本不可确认。
- 自定义答案参与最终选择数量以及 `min_select` / `max_select` 校验。

## 4. 选择中 UI

### 4.1 总体结构

选择界面采用结构化卡片布局，按以下顺序渲染：

1. 标题栏：`SELECT · SINGLE` 或 `SELECT · MULTIPLE`，右侧显示选择计数或限制。
2. 原问题。
3. 答案状态行：答案总数、当前可见范围和选择约束。
4. 可滚动的答案选项区。
5. 滚动状态提示。
6. 固定系统操作区：`Custom option`、`Chat about this`。
7. 快捷键帮助或校验错误。

答案区与系统操作区在模型和视觉上保持分离。两个系统操作固定在底部，不参与答案总数统计。

### 4.2 答案计数与可见范围

状态行仅统计调用方提供的答案，例如：

```text
5 个答案 · 当前显示 1–3 · 至少选择 1 项
```

要求：

- 不再使用含糊的 `more` 文案。
- 当所有答案可见时显示总数，不必显示虚假的剩余提示。
- 当答案被裁剪时，必须同时显示当前范围和剩余方向/数量，例如 `↓ 还有 2 个答案`。
- 用户通过上下方向键可以访问全部答案；不存在“请求提供 5 项但永远只能访问 3 项”的情况。
- 选项区域内部滚动，保持 Select 面板最大高度，不无限压缩上方聊天记录。

### 4.3 视觉状态

每个答案项展示：

- 单选或多选标记。
- `label`。
- 非空时展示 `description`。

高亮项使用清晰的背景和左侧强调线。选中状态与光标高亮是两个独立状态，不能只靠同一种颜色表达。

### 4.4 导航模型

上下导航顺序为：

1. 全部答案项。
2. `Custom option`。
3. `Chat about this`。

即使系统操作固定在底部，键盘焦点仍可从答案列表连续移动到操作区。答案区根据当前答案焦点更新内部滚动位置；系统操作区不计入答案可见范围。

建议继续支持：

- `↑` / `k`：上移。
- `↓` / `j`：下移。
- `Home` / `End`：移动到导航序列起点/终点。
- `Space`：选择或切换当前答案；聚焦 `Custom option` 时进入编辑；聚焦 `Chat about this` 时不执行操作。
- `Enter`：提交当前选择；聚焦 `Chat about this` 时取消 Select。
- `Esc` / `Ctrl+C`：取消 Select。

## 5. Custom option 行为

### 5.1 进入输入状态

激活 `Custom option` 后，在操作区原地切换为单行输入框，不关闭 Select，也不把焦点移到聊天输入框。

- `Enter`：确认非空文本。
- `Esc`：放弃本次编辑并返回选项导航。
- 若已有自定义答案，输入框预填已有文本，确认后覆盖该答案。

### 5.2 单选模式

用户确认自定义内容后保存该答案并返回 Select，不立即提交。用户随后按 Enter 才提交并关闭 Select：

```json
{
  "cancelled": false,
  "selected_options": [
    {"id": "custom_option", "label": "用户输入内容"}
  ]
}
```

保存自定义答案与提交 Select 是两个独立步骤。

### 5.3 多选模式

用户确认自定义内容后：

- 将其作为已选答案加入当前选择。
- 返回答案导航状态。
- 保留此前已选的预设答案。
- 用户可以继续选择其他答案，最后统一提交。
- 再次激活 `Custom option` 时编辑已有自定义答案。

若当前选择数量已达到 `max_select` 且尚无自定义答案，不允许新增，并显示明确错误。编辑已经计入数量的自定义答案不增加计数，应允许进行。

## 6. Chat about this 与取消

激活 `Chat about this` 后：

- 关闭当前 Select。
- 将焦点返回聊天输入框。
- 工具结果与普通取消相同：

```json
{
  "cancelled": true,
  "selected_options": []
}
```

`Chat about this` 与 `Esc` 可在 UI 操作名称上不同，但协议层不区分原因，不增加 `outcome` 或其他状态字段。

## 7. 完成后的 transcript 展示

### 7.1 折叠摘要

完成后的默认折叠状态只占一行，不展示问题或具体答案：

```text
✓ Select · 已完成 · 选择 3 项
```

取消时使用对应的一行状态文案。摘要继续遵循现有 tool transaction 的状态、耗时、焦点和展开交互，但 Select 的 target/preview 不应把答案拼进额外一行。

### 7.2 展开详情

展开后只展示：

1. 原问题。
2. 全部已选答案的标签。
3. 对于预设答案，若原选项有描述，则展示描述。
4. 对于自定义答案，可用弱化的 `Custom option` 辅助说明。

不展示：

- 未选答案。
- 原始 JSON。
- `cancelled`、字段名等协议实现细节。

展开示例：

```text
以下哪些动物属于哺乳动物？

鲸鱼
  哺乳动物，用肺呼吸

蝙蝠
  哺乳动物，具有飞行能力

鸭嘴兽
  Custom option
```

### 7.3 数据保留

为了让工具完成后仍能渲染原问题、标签和描述，tool transaction 必须保留或可解析 Select 的请求输入以及结构化结果。该逻辑应限定为 Select 专用格式化，不改变其他工具继续展示其原始详情的行为。

建议将 Select 详情解析和渲染封装为独立辅助单元，例如：

- 解析 Select 请求中的问题与选项。
- 解析 `selected_options` 结果。
- 将已选结果与请求描述按 ID 匹配。
- 生成折叠选择数量和展开详情。

解析失败时不得让 transcript 渲染崩溃；应退回现有通用工具详情渲染。

## 8. 状态模型与组件边界

`selectionDock` 需要明确区分：

- 答案高亮索引。
- 系统操作焦点。
- 已选择的预设答案集合。
- 可选的单个自定义答案文本。
- 是否处于自定义输入状态。
- 答案列表的首个可见索引。
- 当前错误文本。

建议以焦点类型而非伪造答案项的方式建模系统操作，例如 `answer`、`custom_action`、`chat_action`。这样答案计数、滚动范围和提交校验不会意外包含系统操作。

Result 构造统一由 dock 根据请求选项和自定义答案生成，避免 UI 层之外重复执行 ID 到标签的转换。

## 9. 错误处理

需要覆盖以下错误：

- 请求预设选项使用保留 ID `custom_option`。
- 自定义输入为空或只有空白。
- 多选未达到 `min_select`。
- 新增自定义答案会超过 `max_select`。
- 继续选择预设答案会超过 `max_select`。
- Select 请求或结果无法被 transcript 专用格式化器解析。

交互校验错误在 dock 内显示，并在用户移动焦点、修改输入或完成有效操作后清除。协议解析错误继续返回工具错误；transcript 格式化错误则使用安全回退展示，不影响会话运行。

## 10. 测试策略

### 10.1 协议与输入测试

- `Result` JSON 只包含 `cancelled` 与 `selected_options`。
- 成功与取消时 `selected_options` 均稳定编码为数组而非 `null`。
- 请求拒绝保留 ID `custom_option`。
- 旧 `selected_ids` 不再出现在 Select 的生产代码或快照中。

### 10.2 Dock 状态测试

- 单选预设答案提交返回正确 `id` 与 `label`。
- 多选结果按请求顺序稳定返回。
- 自定义单选确认后保存答案并保留界面，随后由 Enter 提交。
- 自定义多选确认后保存答案并保留界面和已有选择。
- 再次编辑自定义答案时只更新一个结果项。
- 自定义答案正确参与最小/最大选择数量。
- `Chat about this` 与 `Esc` 均返回相同取消结果。
- 上下导航可遍历全部答案和两个固定操作。
- 内部滚动时总数、可见范围与剩余数量正确。
- 短终端中所有答案仍可通过滚动访问。

### 10.3 Transcript 测试

- Select 折叠摘要只占一行且不包含答案标签。
- 展开详情包含原问题、全部已选答案及可用描述。
- 展开详情不包含未选答案和原始 JSON 字段名。
- 自定义答案显示其标签和 `Custom option` 辅助说明。
- 取消状态有清晰单行摘要。
- 非 Select 工具渲染行为不受影响。
- Select 输入或结果畸形时安全回退到通用工具详情。

### 10.4 回归验证

运行：

```bash
go test ./internal/tool/select ./internal/ui/bubble ./internal/loop
go test ./...
```

同时检查窄终端、宽终端、单项、五项以上、长标签、长描述和中英文混排的手工快照。

## 11. 验收标准

本设计完成时必须满足：

1. Select 结果不再包含 `selected_ids`，只返回 `selected_options`。
2. 每个结果项只有 `id` 和 `label`。
3. 自定义答案使用 `id: "custom_option"`，每次最多一个。
4. `Custom option` 与 `Chat about this` 始终可见且不计入业务答案总数。
5. 超出高度的答案可在内部滚动访问，并明确显示总数、当前范围和剩余数量。
6. 自定义编辑器中的 Enter 只保存答案并返回 Select；随后再次按 Enter 才提交当前选择。
7. `Chat about this` 和普通取消返回相同取消协议。
8. 完成后的折叠摘要只有一行，不显示问题或答案。
9. 展开后只显示原问题与已选答案，不显示未选项或原始 JSON。
10. 相关协议、dock、transcript 和回归测试全部通过。
