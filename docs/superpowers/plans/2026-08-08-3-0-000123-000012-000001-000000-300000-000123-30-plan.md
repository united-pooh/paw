# Context Meter 进度条：匀速动画 + 流动发光梯度

计划 ID：`2026-08-08-3-0-000123-000012-000001-000000-300000-000123-30`
日期：2026-08-08

## Background & Goal（为什么）

`internal/ui/bubble/context_meter.go` 的 context usage 进度条当前有两处时间动画：

1. **追赶动画**：`animatedContextTokens` 用 `easeOutBack`（720ms）插值——起步快、收尾慢、结束前有轻微 overshoot。用户希望改成**匀速**。
2. **脉冲高亮**：`contextPulse(progress)` 返回 `sin(progress·π)`，`contextUsedPulseStyle` 让 used 区**最后 2 格**在动画期间整体亮灭。用亮度抽象观察到的帧序列是：

   ```
   000123, 000012, 000001, 000000, 300000
   ```

   其中 `300000` 是动画重启（usage 又变化、fromUsed 很小时）出现的：脉冲格是"used 区末尾"，used 区很短时末尾即开头，最亮点突然出现在进度条最左端，破坏连续性。

目标视觉效果（亮度 3 最亮、0 无亮度，梯度三元组 (1,2,3) 作为整体绕进度条**环形右移**，永不熄灭、永无跳变）：

```
000123 → 300012 → 230001 → 123000 →（循环回 000123）
```

这样光带有传送带式的流动感。已与用户确认：流动效果**仅在动画期间显示**（usage 变化后的 720ms 内），动画结束熄灭恢复普通样式（与当前脉冲的触发时机一致，空闲时不耗渲染帧）。

## Behavior & Functional Content（精确行为）

### 1. 匀速追赶动画

`animatedContextTokens` 中：

```go
const duration = 720 * time.Millisecond
progress := clamp01(float64(elapsed) / float64(duration))
eased := progress // 线性匀速（原 easeOutBack）
```

`animatedUsed` / `animatedCache` 仍为 `lerp(from, to, eased)` + `math.Round` + clamp，只是 eased 从缓动曲线变为线性。删除 `easeOutBack` 函数（无其他调用者）。

### 2. 流动发光梯度（取代脉冲）

**相位来源（无状态，从时间推导）**：`animatedContextTokens` 第三返回值从 `float64 pulse` 改为 `int phase`：

```go
const flowInterval = 100 * time.Millisecond // 约 3 帧/格，可调
var phase int = -1                          // -1 = 不流动
if progress > 0 && progress < 1 {
    phase = int(elapsed / flowInterval)
}
return animatedUsed, animatedCache, phase
```

- 未初始化（`!initialized`）时返回 `-1`。
- 动画结束（`progress >= 1`）返回 `-1`（熄灭）。
- 动画期间 phase 单调递增（0, 1, 2, …），渲染端对 usedCells 取模，天然循环，无需帧计数状态。

**亮度函数**（新，纯函数）：

```go
// contextFlowBrightness 返回格子亮度 0-3（3 最亮）。梯度三元组 (1,2,3)
// 绕 used 区环形右移：phase 每 +1 图案右移一格。
func contextFlowBrightness(phase, index, usedCells int) int {
    if phase < 0 || usedCells <= 0 || index < 0 || index >= usedCells {
        return 0
    }
    d := ((usedCells-1-index+phase)%usedCells + usedCells) % usedCells
    if d > 2 {
        return 0
    }
    return 3 - d
}
```

**序列验证**（usedCells=6，与用户规格逐帧一致）：

| phase | index 0..5 亮度 | 图案 |
|---|---|---|
| 0 | 0,0,0,1,2,3 | `000123` |
| 1 | 3,0,0,0,1,2 | `300012` |
| 2 | 2,3,0,0,0,1 | `230001` |
| 3 | 1,2,3,0,0,0 | `123000` |
| 4 | 0,1,2,3,0,0 | 继续右移，循环 |

**样式映射**（新 `contextUsedFlowStyle`，取代 `contextUsedPulseStyle`）：

```go
func contextUsedFlowStyle(phase, index, usedCells int) lipgloss.Style {
    switch contextFlowBrightness(phase, index, usedCells) {
    case 3:
        return contextUsedStyle.Copy().Foreground(colorManager.LipglossColor(colorMarkdownHeading)).Bold(true)
    case 2:
        return contextUsedStyle.Copy().Foreground(colorManager.LipglossColor(colorMarkdownHeading))
    case 1:
        return contextUsedStyle.Copy().Bold(true)
    default:
        return contextUsedStyle
    }
}
```

亮度 0 = 普通 used 样式；1 = 加粗；2 = heading 前景色；3 = heading 前景 + 加粗（即原 pulse 最亮样式）。三级递增，3 最亮。

**渲染管线签名变更**：

- `renderContextMeterLine(width, usedLabel, freeLabel, used, cache, limit, overlay, pulse float64)` → 末参 `phase int`。
- `renderContextBarWithOverlayStart(..., overlayStart int, pulse float64)` → 末参 `phase int`；格子循环中 `contextUsedPulseStyle(pulse, i, usedCells)` → `contextUsedFlowStyle(phase, i, usedCells)`。
- `renderContextBar(used, cache, limit, width, overlay)` 内部调用 `renderContextBarWithOverlayStart(..., -1)`（卡片路径不流动）。
- `contextMeterLine` 中 `m.animatedContextTokens(limit)` 的第三值直接透传。
- cache 区（`i < cacheCells`）与 free 区（`i >= usedCells`）分支不变；overlay（thinking 标签）居中逻辑不变。

## Acceptance Criteria

1. 进度条追赶动画匀速：`animatedUsed` 随 elapsed 线性插值，不再有起步快/收尾慢/overshoot 行为；720ms 时长不变。
2. 动画期间 used 区显示亮度梯度 (1,2,3) 环形右移，帧序列严格匹配 `000123 → 300012 → 230001 → 123000 → …` 循环（宽度 6 时）；3 最亮、0 无亮度。
3. 动画结束（elapsed ≥ 720ms）或未初始化时无任何高亮（phase = -1），进度条恢复普通样式；卡片进度条不显示流动。
4. 流动只作用于 used 区；cache 区、free 区、thinking overlay 渲染不变。
5. 标签数字动画（easeOutCubic 400ms）与触发机制（`updateContextMeterAnimation`）不变。
6. `go build ./...` 与 `go test ./internal/ui/bubble/` 全部通过，无残留对 `easeOutBack`/`contextPulse`/`contextUsedPulseStyle` 的引用。

## Open Questions

- `flowInterval = 100ms`（约每 3 帧移动 1 格，720ms 内移动约 7 格）是建议值；如实测流动太快/太慢，可调该常量（行为规格不变）。
- 亮度 1/2 的具体样式（1=加粗、2=heading 色、3=heading 色+加粗）是实现建议；只要保持"3 最亮、0 无亮度、中间两级递增"即可替换实现细节。
