# Goal 与 Plan

[文档导航](../README.md)

## Goal：给指标，自主探索方法

Goal 用于「知道怎样验收，还不知道怎样实现」的任务。例如：

```text
/goal start 在固定测试集上把准确率提高到至少 90%，实现方法由你探索。
```

模型先调查当前实现、建立评测方法，再反复提出假设、修改、测量、分析差距。未达标时可以推翻原路线，TODO 只是当前尝试的工作清单；清空或完成 TODO 都不代表 Goal 完成。指标、单位或评测条件有歧义时应先澄清。

验收记录包含指标名称、`gte` / `lte` 比较方向、阈值、单位及评测口径。模型用 `goal_set_metric` 固定这些字段；通过普通 `Bash` 执行评测，再在下一批工具调用中用 `goal_record_metric` 引用该调用的 ID。宿主从真实工具结果提取数字，工具不接受模型自报的值或 `passed`。

当前评测接口要求 Bash 输出完整 JSON，按固定 JSON Pointer 提取一个有限数字。例如 `./bench --json` 输出 `{"p95_ms":42}`，路径为 `/p95_ms`，验收为 `lte 50 ms`。命令、目录、路径和阈值固定后不可放宽；失败、非 JSON、历史调用、重复调用或不匹配的输出不能作为新验收证据。模型可以先构建评测方法，再冻结口径；这不要求你预先给出实现步骤或编写评测命令。

宿主核对工具调用与数值，评测脚本是否准确反映实际需求仍需要测试和审查。单一数值不能替代数据集质量、实验设计或产品可用性验收。

运行时直接输入补充条件会加入当前目标。`/goal status` 查看目标、指标和测量；`/goal pause` 暂停；`/goal resume` 继续同一目标；`/goal cancel` 取消。暂停不是完成，恢复保留原目标和历史测量。每次恢复开启新的有限执行窗口，累计用量保留；遇到预算、连续无进展或需要用户输入会停下并说明原因。

## Plan：持续讨论，明确执行

```text
/plan new 讨论如何改造缓存层
```

Plan 在当前对话调查、澄清和修改方案。普通回复后等待下一条输入；模型调用 `plan_finalize` 保存后进入 `ready`，界面显示计划路径和执行入口，不自动启动实施。

输入修改意见会继续同一个计划，并使先前的 ready 状态失效。重新保存后，用户通过 `/plan execute` 明确批准当前文件，再交给普通执行模式实施。模型调用保存工具本身不能批准执行。

Plan 允许读工作区、写计划目录，不运行 Bash 或修改业务文件。`/plan status` 查看状态；`/plan stop` 暂停；`/plan resume` 恢复；`/plan cancel` 取消。

两种模式都优先识别控制命令；无法接纳的补充输入保留在草稿里。恢复历史会话不会自动启动任务，按界面提示使用对应模式的恢复命令。
